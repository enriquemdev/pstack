# Antigravity adapter

Explicitly invoke `/pstack-how` or ask to use `pstack-how`.
Use `/pstack-poteto-mode` for the current task. Antigravity surfaces differ: verify
the installed app/CLI version and live tool catalog instead of assuming parity.

- Use the host's file, terminal, browser, plan and artifact tools within their policies.
- Use the current model. Do not translate Cursor model slugs into guessed Google tiers.
- Use native project history or Engram when available, never Cursor transcript paths.
- Use GitHub connectors or authenticated CLI operations, not Cursor Origin/cloud APIs.
- Only after explicit human authorization, use `invoke_subagent` IF that tool is
  advertised in the current session. Provide the full brief and scope because context
  inheritance differs across surfaces. Do not assume named agents are registered.
- Without available authorized subagents, work sequentially and disclose that limitation.
  Never claim that repeated self-review is independent or multi-model review.
- Workspace skill discovery uses `.agents/skills`. Global locations differ by surface:
  IDE: `~/.gemini/antigravity/skills`; 2.0: `~/.gemini/config/skills`;
  CLI: `~/.gemini/antigravity-cli/skills`. Select the surface explicitly when installing.
- There is no verified equivalent here for Codex's `allow_implicit_invocation` metadata.
  Skill descriptions therefore require an explicit human pstack request or a deliberate
  routing call from an already invoked pstack skill. This is an instruction-level gate,
  not a guaranteed runtime enforcement mechanism.

Read `references/policy.md` before executing the skill. Never alter permission settings
to make a workflow pass. Mark missing integrations blocked, not successful.
